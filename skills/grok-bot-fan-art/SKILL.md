# Grok Bot 粉丝图

这是 **Grok Bot 环境专用**技能。流程依赖这个 Grok Bot 里已经授权的 X 连接（用户连接的名字可能会变，常见是 user-X）。它不表示世界上只有 Grok Bot 能使用 X 的 API。浏览器扩展的采集、评分和绘制代码保持原样；本技能不修改扩展行为。

做评分前读 [references/scoring.md](references/scoring.md)。做切图前读 [references/slicing.md](references/slicing.md)。运行记录的字段见 [references/run-record.md](references/run-record.md)。记录留在本地，不要把名单、关系或图片提交到 GitHub。

## 先决条件

1. 运行时先读取并遵守 Grok Bot 的 X API / MCP 指南（技能名常见为 `x-api-mcp-guide` 或 “X MCP guide”）。不要凭记忆调用。
2. 发现**当前** live 工具的 schema 再用。下文的工具名只是编写时的例子，调用名和参数会变，不能当成永远固定的 schema。
3. 读自己的账号（粉丝、自己的帖、自己的头像）走已授权的用户连接。公开读（他人公开帖、公开用户）遵循该指南：可以用 Grok Bot 的公开读工具。写操作只有用户明确要求时才做。
4. 不要索要或接受 bearer、token、API key、密码。不要自己请求 `api.x.com`。不要在浏览器里登录 X。不要绕过连接权限、scope 或计费失败。
5. 401、没有 X 工具：请用户重连该连接，然后重试一次。403 点名某个 scope，或某一类工具缺失：连接没有该权限，请用户重连并授权，不要换路径绕过。429：按响应里的 `x-rate-limit-reset` 等待后再试一次。返回缺少 `developer.billing.write` 或其它计费开通错误时，**不要**尝试开启计费。
6. 额度以**当次工具提示和平台限制**为准，动态放慢或停止。编写时曾见到「每次最多 25、每分钟 30、每日至 1000」这类提示；那不是永久保证，改版后不要继续沿用旧数字。
7. 默认只生成图片。不发帖、不点赞、不 follow、不发 DM、不读私信、不创建自动监控或定时任务。用户明确要求发布时，才按 X 指南的发帖规则另走，并先出示全文。

## 步骤

### 1. 确认这次要哪种图

只做用户要的那一种，并在记录里写明：

| 输出 | 含义 |
| --- | --- |
| 网格墙 | 每个粉丝恰好一格。这不是 FanOrbit。 |
| FanOrbit | 仓库里的同心圆或方环。中心倍率只用 2、3、4。必须跑真实布局函数，不能把仿制图说成项目输出。 |
| 角色 photomosaic | 用 Pillow 做颜色匹配的自制拼图。成功取得头像的账号默认每人 1 到 2 次。FanOrbit **不是**角色马赛克工具，不要把环状头像墙叫 photomosaic。 |

没有互动数据时，标记「无互动排序」，不要编造分数。用户没要求顺序时，FanOrbit 项目默认会把无分粉丝洗牌，交付里写成随机顺序。用户要求保持原名单顺序时不要洗牌，并写明按原顺序。两种都不是互动排序。

要改仓库里的布局或扩展代码时，交给 Grok Bot 的云端 code-changes。图像渲染可以在本机用已经下载的头像完成。禁止自己 `git clone` 这个仓库。

### 2. 本人与粉丝

用当前 schema 里读取已授权用户的接口（编写时的例子是 `get_users_me`）取得数字 id、公开粉丝数和真实头像 URL。把 id 记为 `{me}`。目标角色的中心图或 photomosaic 目标图只用这张真实头像，或用户另行提供的参考图。不要根据外貌描述生成一张脸，再把它叫做对方的真实头像。

粉丝列表用当前 schema 里「我的粉丝」分页接口（编写时的例子是 `get_users_me_followers`）。`user.fields` 至少请求 `username` 和 `profile_image_url`，以当时 schema 允许的字段为准。用 `meta.next_token`（或当时 schema 的下一页字段）作为 `pagination_token` 继续，按用户 **id** 去重，直到没有下一页。

在 [运行记录](references/run-record.md) 里写下：获取时间、接口给出的公开粉丝数、去重后的唯一 id 数、分页是否在 next_token 耗尽时结束、因额度停在哪一页、下载失败的 id。分页没结束或额度用尽时，这是**样本**，不能写成全量粉丝。公开粉丝数和唯一 id 数不一致时，并列两个数字和分页是否结束；不要仅凭差额自动宣称漏了人。

### 3. 下载头像

只下载工具实际返回、且用 URL 解析后 `hostname === 'pbs.twimg.com'` 的地址。必须是主机名相等；`evilpbs.twimg.com` 这种后缀不算，不要用「以 `pbs.twimg.com` 结尾」判断。其它主机不下载。不要把文件或 URL 交给第三方拼图网站。

- 小并发（遇 429 或超时时再降低）、有超时、有限次重试。
- 高清变体只在上面的主机名检查已经通过、且路径含 `/profile_images/` 时尝试：把文件名末尾的 `_normal`、`_mini`、`_bigger`、`_reasonably_small`、`_200x200` 换成 `_400x400`。`lib/util.js` 的 `upscaleTwitterAvatar` 用 `hostname.endsWith('pbs.twimg.com')`，后缀伪造的主机也会通过；Bot 不要沿用这个判断。变体必须先确认 HTTP 成功且图像能解码，失败就用工具返回的原 URL。扩展本身不解码校验；Bot 必须校验。
- 默认头像解码成功也是有效粉丝，不要悄悄删掉。
- 文件名用数字 id，例如 `{id}.jpg`。不要用未经净化的用户名当路径。
- 同时写 JSON 和 CSV 清单，字段见运行记录。已有且能解码的 id 跳过下载，分页仍要继续，直到下一页没有或额度用尽。下载失败的人留在名单里并记下原因，不能从粉丝集合里消失。

### 4. 公开互动与排序

只有用户要求按互动排，或 FanOrbit 需要内环顺序时才采集。范围是用户指定的窗口；没指定时用一个说清楚的最近窗口（例如 30 天），并记下确切的起止时间。

从已授权的官方 X 连接收集**公开**事件：用户自己的帖（含回复）、提及、以及指南允许的搜索。按当时 schema 分页到没有下一页，或记下截断。编写时搜索侧常见字段是 `start_time`、`tweet.fields=created_at,...`、`expansions`。调用前以 live schema 为准。

记录：窗口、查询、采样方法、每路分页是否结束、没有请求到的日期、接口截断或每页上限。某次响应最多几十条、或隔日只拿到有限几条时，不能说成完整一个月。没有证据就不要补事件。不读私信。分数只描述这次采到的公开事件，不代表现实中的亲密程度。

事件形状、去重、入站只留一种类型、出站可以一帖多事件、权重、`timeWeight`、`balance`、三位舍入，以及上墙 tie-break，全部以 [references/scoring.md](references/scoring.md) 为准。云端工作副本里优先调用 `lib/scoring.js` 的 `computeScores`。本机只有事件 JSON 时按该参考复现，并写明「公式复现」和冻结的 `now`。换了数据源之后只能说**评分公式相同**，不能说数据与浏览器扩展（fxtwitter / Yahoo / Bing）完全相同。

`colorSort` 为真时，项目改为按头像色相排序，互动顺序整段失效。见评分参考。

### 5. 用户要求某些人一定入图

用户要求常聊者或点名的人必须出现时：

```text
must_include = 用户点名的账号 ∪ 本次公开事件里有双向证据的候选
```

双向证据指同一人在本次采集里既有入站事件、也有出站事件。默认纳入这个并集的**全体**。不要擅自截成一个 top-N。曾经把必选集合截成任意前列，点名和有双向证据的人会被漏掉；改为保留全体双向候选后才补齐。用户若明确只要前几名，只对网格墙或 FanOrbit 的排序展示截断，并在交付里写明这是用户要求的截断。角色马赛克不因这句丢掉解码成功的账号。

点名的人不是粉丝时，标明「不是粉丝」。只在已授权的公开读范围内另取头像。取不到就报告缺失原因，不要悄悄丢掉。

颜色匹配、格网美观是软目标。必选是硬约束：每个必选 id 至少出现一次，尽量放在看得清、靠内或靠近主体的位置；分数高的优先靠内。不能为了放入一个人而换掉另一个必选者的唯一一格。

渲染后做程序断言：placement 映射里每个 must_include 的 `count >= 1`。把每个必选 id 的坐标、次数和缺失原因写入本地运行记录。有人进不去时，交付里明确列出缺失 id 和原因，不要把这轮说成已经满足。

角色马赛克的覆盖范围比这段更大，见下一节的硬约定。成功取得头像的粉丝本来就要入图，不能因为没有双向互动就被当成可省略的非必选。

### 6. 布局

**网格墙。** 每个粉丝 id 恰好一次。顺序在没有互动数据时用采集顺序，并标记无互动排序。有分数时按评分参考的上墙顺序，无分的人放在有分的人之后，保持稳定顺序，不要假装他们有分。

**FanOrbit。** 调用仓库里的真实函数，不要用笔记重写一套环：

- 条数与中心倍率：`lib/layout.js` 的 `normalizeSplitParts`、`normalizeSelfScale`、`fitSplitParts`、`planCuts`
- 环与槽位：`generator.js` 的 `drawOrbitFromItems`

中心倍率只接受 2、3、4；非法值会被 `normalizeSelfScale` 收成 2–4，默认 3。形状是 `circle` 或 `square`。粉丝边长沿用项目的 `clampInt(..., 40, 300, 96)`，默认 96，除非用户指定范围内的其它尺寸。背景默认 `#f5f3ff`。

项目在无分时会 `shuffle` 无分粉丝，每环还有 `Math.random()` 转角。要可复现就保存这次的槽位 JSON，不要指望再跑一次坐标相同。交付时说明坐标来自哪一次真实函数运行。仿制几何必须标明「不是 FanOrbit 函数输出」。

**Photomosaic。** 远看是目标图，近看每一格仍是可辨认的小头像。输出总览、高清全图，以及可选的近景裁切，并目视看过远近两档。身份覆盖和次数是硬约束，颜色还原是软目标。不要把目标图以高不透明度盖在拼图上冒充马赛克。允许轻度、可关闭的调色来帮轮廓，调完仍要认得出是那张头像。交付里写明颜色和识别度各牺牲了什么。

覆盖集按数字 id 去重：

```text
C = 解码成功的粉丝 ∪ 用户点名的非粉丝等额外 must_include（也要有解码成功的头像）
N = |C|
```

下载失败、没有可用 URL、或额外点名却没取到头像的 id 留在缺失名单里，写明数量和原因。不要把他们从粉丝清单里删掉后再宣称全员入图。「全员」只表示 C 里每个 id 都出现了，并且缺失名单已单独给出。默认头像只要解码成功就留在 C 里。

默认每个账号最多出现 2 次。相同图像的不同账号按账号分别计数，另报「与其他账号共用同一图像」的账号比例；默认头像照实计入该比例，不要先排除。只有用户明确改口时才改变 1..2 这个上下限，并在记录里写 `capChangedByUser`。

放置顺序：

1. 先给 C 里每个 id 恰好一格。点名者、有公开双向互动的常聊者，以及高分、靠近主体的格子，在这一步定下之后就不能被颜色优化挤掉或换成别人。
2. 再用剩下的空位做全局颜色优化。需要第二次出现时，把重复格放得离第一次远，也远离同一 id 的其它格，避免边相邻和局部扎堆。
3. 颜色再近，也不能让某个 id 变成 0 次或超过约定上限，也不能挪走上一步保护的格子。

设有效头像格数为 T（留白不算）。必须满足 `N <= T <= 2N`（用户改过上限时，把 `2N` 换成 `N × 该上限`）。不满足就改网格密度、画布尺寸、有效格数，或把多余格子留白。不要靠第三次及以上的重复，也不要删掉 C 里的人来凑这块图。留白可以用来把重复格隔开。

渲染后按 id 实际计数，不通过就不要说马赛克完成：

- C 中每个 id 的次数都在 1 和上限之间，未使用账号数为 0。
- 每个额外点名且头像解码成功的 id 次数不少于 1，并落在保护格上。
- 同一 id 的重复格尽量没有四邻接；做不到时记下剩余邻接数，仍然不能超限或删人。
- 报告总格数、有效头像格 T、唯一账号数 N、唯一图像数、重复格数和比例、缺失与下载失败的数量及原因、实际出现过的最大次数。总格数不是人数。相同图像比例单独写，不能把它当成账号次数。

### 7. 切图

条数、方向、是否奇数、是否等宽，都由当次用户要求、实际图尺寸、画面里的头像和中心，以及**当时**目标平台的能力决定。不要写死 15 条、20 张或「永远奇数」。用户指定了条数或版式就优先照做；做不到时说明原因并给出做得到的方案。用户没指定时，自己选一个能看清头像、切线不穿头、按顺序能拼回的方案，并写明理由。

平台一次能发几张、像素上限、长宽比都不是永久事实。先查当前工具或页面能力。查不到就写「未确认」，不能保证 X 一定接受某一张数。又窄又长的条如果当时发不出去，就减少条数、改成多行、改成方片，或先给预览。不要为了凑满某个张数把图切坏。

网格按整格或砖缝切。FanOrbit 若走项目分图，用 `planCuts` 把切线留在头像走廊里。项目函数会把条数收成奇数且不超过 19，并可能因为画布不够而减少；这是函数结果，要原样报告。用户要的条数是该函数不会产出的（例如偶数、或多于它的上限），就在成图之外另做切割，并标明这不是 `planCuts` 的返回值。细则、校验和 JPEG 与无损母版的差别见 [references/slicing.md](references/slicing.md)。

### 8. 交付

给出统计、预览、高清全图，以及按顺序命名的切片压缩包。切片文件名 `01`…`NN`（位数按张数补零）。保留本地无损高清母版。

附件上限以**当时**聊天或工具的限制为准，不要沿用旧笔记里的兆数字。超过上限时压缩，或拆成几份各自能单独打开的完整压缩包（例如按文件名区间各打一个 zip）。不要做必须拼在一起才能解压的分卷。

不要把原始粉丝名单、互动关系、头像文件或运行记录提交到 GitHub。本技能目录里只保留不含具体用户的说明。
